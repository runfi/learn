第 13 章 / 02学习范围、关键机制与复习问题

前置：12 的对照评估。目标：根据任务与证据选择协作方式，而不是用 Agent 数量代表能力。

小课核心问题与机制纸面推演 / 后续验证
13.1 何时拆分单 Agent 工具并行、子任务委派、多 Agent、固定工作流的差别B 资料核验是否值得拆分，先有单 Agent 基线
13.2 交接契约目标、上下文、预算、权限、产物、完成条件与证据；独立/共享状态子 Agent 返回结论但无依据时，父 Agent 不能直接宣布完成
13.3 协调与收敛消息、共享存储、冲突、去重、失败传播、取消、合并与全局预算一个子任务失败或过期，整体状态如何解释
13.4 框架承担什么手写循环、图工作流、持久执行框架；模型/工具协议与 Agent 通信协议按状态、恢复、可观测性、耦合和迁移成本比较
13.5 协作评估重复劳动、上下文隔离收益、通信开销、错误相关性、关键路径延迟使用 12 的评估方法决定保留单 Agent 还是协作

验收：给出拆分或不拆分的理由；不预设多 Agent 更准、更快。RSI 候选生成可作对照场景，不强制启动多个 Agent。

FAQ / 示范答法：

  • 多 Agent 一定比一个强吗？ 不一定。拆分可能隔离上下文或并行工作，也增加沟通、重复和结果合并成本，得与单 Agent 基线比较。
  • 给每个 Agent 一个角色描述就够了吗？ 还需要任务边界、输入、权限、输出证据和失败处理。角色名本身不能形成可靠协作。
  • 为什么不用现成框架？ 我会先看框架是否解决实际的状态、恢复和观察需求，再权衡学习成本与耦合；手写也不是天然更好。
