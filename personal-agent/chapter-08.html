第 08 章 / 02学习范围、关键机制与复习问题

前置：06 的数据正本、07 的检索、05 的加载。目标：跟踪一条信息从出现到写入、召回、纠错、整理和遗忘。

小课核心问题与机制纸面推演 / 后续验证
08.1 记什么显式要求、稳定偏好、已验证事实、可复用经验；一次性状态、猜测和敏感内容的处理策略A 与一次性例外分别决定保存/暂存/拒绝及理由
08.2 谁自动写模型提候选、规则/程序校验；用户请求、turn 结束、事件、压缩前、定时扫描等触发选择显示提取输入、候选、接受/拒绝、写入结果；禁止虚报已记住
08.3 怎么更新原始记录、文件/表正本、claims、画像、索引、缓存；去重、冲突、版本、有效时间A2 更正；显式更正和推断竞争；旧后台结果不能覆盖新版本
08.4 读什么任务需要、身份/范围/权限、有效期、来源可信度；精确读与检索、重排、预算、注入展示候选、排除原因、最终读入；缓存版本和索引延迟可解释
08.5 Dreaming历史回放、合并重复、发现矛盾、提炼经验、重组目录；与普通摘要/在线写入的差别一次批处理给出前后差异，每条变更有来源；不能从重复生成文本制造“证据”
08.6 后台协调扫描窗口、水位、输入快照、候选变更、校验、条件提交、索引刷新；中止/重试/预算先手动触发同一批次两次，再加入并发更正；可靠调度留 09
08.7 遗忘与控制过期、衰减、归档、停用、删除、墓碑、备份边界、后台再生成阻断A3 删除后查正本/索引/缓存，再运行旧整理任务，防止复活

必须讲清的自动读写策略：写入不是每句话保存，读取不是每次搜索全部库。分别比较同步显式写入、当前轮自动候选、后台批量提取；比较常驻少量核心偏好、任务相关检索、模型按需查询。说明什么时候跳过、误记与漏记如何纠正，自动化范围由产品规则与用户控制决定。

Dreaming 的完整设计练习：触发 → 选定事件区间与正本版本 → 生成带来源的候选差异 → 检查重复/冲突/范围 → 提交或作废 → 更新派生索引 → 记录成本与效果。每个批次保存输入水位、候选 ID、来源、父版本、拒绝原因、提交状态。08 重点是数据和算法选择；09/10 再处理 worker 崩溃、并发、隔离与权限。是否需要独立子 Agent 是设计选择，不是 Dreaming 定义。

四个边界：自动记忆解决值得保留什么；Dreaming 整理已有经历与记忆；压缩减少当前上下文负担；RSI 改进 Agent 的策略/实现及后续改进能力。它们可以协同，但不会自动改变模型权重，也不能由一个文件名判断产品具备哪种机制。

验收：用户能追踪一次自动记忆和一次 Dreaming 的输入、候选、提交、索引及后续读取；对并发更正或删除后的旧批次，解释为什么接受、拒绝或重新计算。不能只展示“整理成功”的提示。

FAQ / 示范答法：

  • 自动记忆怎么避免乱记？ 我会把提取和接受分开：模型提出候选，程序检查来源、范围、有效期和冲突。一次性的安排不能直接变成长期偏好。
  • Dreaming 就是晚上跑个总结吗？ 定时只是触发方式。关键是回看哪些经历、提出什么记忆变更、怎样核对来源和冲突，再决定是否写入；整理也可能变差，需要评估。
  • 删掉记忆为什么还可能回来？ 旧历史、摘要或排队中的任务可能再次提取它。设计里要明确遗忘范围，并让后台写入检查删除标记和版本，不能只删一个向量。
